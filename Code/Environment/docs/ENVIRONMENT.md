## Wind, grass, tree wind, chopping, traps (`Code/Environment/`)

- WindSystem (scene wind: host owns heading + base strength via [Sync], every client simulates gusts; publishes WindDirection / WindStrength / WindGust to all shaders through Scene.RenderAttributes once per frame)
- GrassPatch + GrassScatterer (grass through the engine Sandbox.Clutter system — GPU instanced/culled/LOD; shader Assets/shaders/grass_blade.shader, models grass_clump1–4 from Blender/scripts/create_grass_clump.py)
- World grass = TerrainWorldManager.Grass.cs: ONE ClutterComponent in INFINITE streaming mode (a ring of tiles the engine keeps around the camera — ALWAYS 12 tiles, so Grass — Range (m), default 150, picks the tile size) planted on the loaded chunks' meshed height grids (BuildResult.HeightsZ, bilinear — no physics, no collider, nothing else can be hit); a chunk arriving / remeshing invalidates its tiles; ONE density, grass_blade.shader thins clumps by camera distance (Thin Full / Far / Keep / Cull on grass_blade.vmat); console grass_toggle; Clover Hills only via an 8×8 biome mask cached per chunk (64 pipeline samples — built on the chunk's sampling worker since 2026-11-04, `PendingChunkBuild.GrassMask`, so a chunk finish no longer spends ~1.2 ms of the frame on it)
- Wind arrow: TerrainMinimapHud draws "wind" + an arrow under the zoom buttons (map orientation, points the way the wind blows, brightens with gusts; hidden without a WindSystem)
- Tree wind = pixel_lit.shader's F_WIND feature (vertex stage, same WindDirection / WindStrength / WindGust inputs as grass_blade): trunk lean + slow rock from object-space height, limb bob / flap from radius off the trunk axis, optional leaf-card rustle — no vertex colours, weights are continuous in position so faceted meshes never tear. Only the STANDING elm gets it: elm_bark_v76_wind.vmat + elm_leaves_v76.vmat (written by create_elm_tree.py); stump, log and halves keep the static bark. Rumple's clover tree (cloverhills/bark.vmat) is deliberately left alone (Mark 2026-10-13). Knobs are metres on the vmat ("Wind" group: Tree Height, Crown Radius, Trunk Sway, Limb Bob, Fade Start / End …). The shader's strength / gust DEFAULTS are 0 and every term is proportional to them (ONE bend per tree, a ROTATION about the root with the angle growing up the trunk — never a stretch — swinging from past upright to 1.4x the lean; limbs rotate about the trunk axis so downwind limbs dip, upwind lift, both compress; WindGust is one scene-wide value so every tree leans together; leaf cards wiggle in their own random direction / rate / phase hashed from the card's face normal, so nothing tears and no two cards jiggle alike; grass gusts are a drifting value-noise field in grass_blade.shader, not sine bands), so trees only move while a WindSystem is publishing (play mode, scene has one — testscene1 + terrainTest do; WindSystem "Wind Enabled" / console wind_toggle switches it off live; windtest [1-5] = wind perpendicular to the camera (toward its right) + a forced gust of that strength HELD until a plain windtest; 3+ exceeds the normal gust ceiling, 5 = hurricane ×2.5, the usable max — the shader does not cap the gust); the editor viewport is still (Mark 2026-10-12). Sway fades out Fade Start → Fade End metres from the camera (300 → 360 on the elm). Shadow passes must sway identically to the main pass (a cheaper shadow sway self-shadowed the displaced crowns blue) and the vertex stage skips the math past it.
- MineableRock — breakable rocks, sectioned boulders and spires (AGENTS.md *Mineable rocks*); its debris is ChopDebris, the stone drops where the debris comes to rest.
- ChopableTree — two tree types on one component. Type 1 felling (elm): tree → its stump + one universal pointy log that tips over → log splits into two halves → halves / stump drop wood. Type 2 crown fall (clovertree_chop: a disabled "chop_crown" child = one rigidbody whose colliders are Rumple's butt / fork / top "chop_piece" children): tree → stump, the crown tips over away from the chopper (ChopFallingCrown), on landing it splits into the pieces (local ChopDebris, gone after Piece Lifetime) and the host drops the wood there. Stages broadcast via WorldScatterIdentity. Models Assets/models/environment/cloverHills/trees/cloverTree/, bark shared from materials/environment/cloverHills/trees/cloverTree), harvest yields, teleport pads
- SunShadowDistance (on the scene Sun: multiplies the engine's cascade shadow reach so the shadow ring is not at the player's feet)
- BearTrap (hammer-placed trap_small / trap_large: holds players 5 s, animals + enemies 10 s by TrapSize band; hold lives on PlayerMovement.TrapLocked / EntityLocomotion.IsTrapped)
- DamageOverTimeTrap (scene hazard volume)

## Sky and day / night (`Code/World/Environment/`)

- EnvironmentDayNightCycle (sun / moon arc, day counter) feeds SkyDome (camera-centred sphere, shaders/environment/sky_dome.shader: gradient + sun glow + two wind-scrolled cloud layers from sky_clouds.png, Blender/scripts/create_sky_clouds.py) from SkyPresetCatalog (Assets/data/sky_presets.json — per-weather night / dawn / day / noon / dusk keyframes); stars are a procedural layer in sky_dome.shader (StarVisibility from the cycle)
- sky dome + cycle live in lightingTest (3-minute loop, drives the AerialPerspective haze colour), testscene1 (5 min day / 4 min night, no haze) and terrainTest (the lightingTest 3-minute group copied as one "DayNightCycle" object — ENABLED by default since 2026-10-21 (Mark: "it should be running the short daylight cycle") — cycle + sky dome + disks + moon, driving the scene Sun; console cycle_toggle switches it on / off; since 2026-11-03 (Mark: "10am when the terraintest loads … the daylight cycle should be on 20 minutes") a 20-minute loop — Day 500 s / Night 500 s / Dawn-dusk blend 100 s each — starting at **Start hour (0–24)** 10); **Start hour** replaced "Start at night": the sun turns at a constant rate, so hour h is cycle point (h − 6) / 24 (6 = sunrise, 12 = noon, 18 = sunset), default 6 keeps the other scenes at sunrise, and the clock holds while the world load screen is up (`TerrainWorldManager.IsLoadScreenUp`, generating + settling) so the scene opens on the start hour; console cycle_day / cycle_night jump to noon / midnight (the Y / U hotkeys were removed 2026-11-03: the U action fired while Mark flew the fly camera and snapped the world to midnight)
- **Caldera ring** (2026-11-03, Mark: "we live in a caldera … a MASSIVE mountain ring encircles the whole map, 5000 m+ tall, always visible and never cut by view distance, fog or streaming"; then "VERY flat … some ridges lower, or more jutted out toward the player … should feel real not like a wall of rock"): `CalderaRing` on its own "CalderaRing" object at the scene ROOT of terrainTest (+ its ModelRenderer) builds ONE render-only polar heightfield round the world origin — backdrop only (no collider, no streaming, no LOD, no shadows; the generator is untouched, the rim ocean runs to its foot). It must not sit under the DayNightCycle group: `cycle_toggle` switches that group off, which used to take the mountains with it; the ring finds the cycle once at start (enabled or not) and keeps lighting from the root Sun while the group is off. Shape in metres (Shape group): **Foot Radius (m)** 23 000 (the 22.5 km world edge + 500 m), **Range Depth (m)** 11 000 (foot → main crest, ±25 % round the ring), **Saddle Height (m)** 3200 and **Peak Height (m)** 7000 (smooth ~10 km massifs carry the slopes and set the saddles; sharp ~2 km summits sit only on the top, so a peak never runs down the face as a seam), **Ridge Spacing (m)** 3000 and **Ridge Reach (0–1)** 0.9 (ridge arms run down from the crest toward the caldera, each rolling its own reach — some die near the crest, some carry height almost to the foot — and swing sideways up to ~2 spacings on the way down so they read as diagonal ridgelines, not end-on pleats; valleys between them stay low and dip under the sea near the foot as inlets), Seed; knobs and false summits on top, a 900 m apron under the ocean floor, a 6 km back slope. 1536 columns × 47 rows, faceted in the shader. Vertex colour by grade: basalt cliffs with oxidised tuff strata where steep, grey-brown scree on gentle ground, ash on high gentle ground, valleys darker than the arm crests. `shaders/environment/caldera_ring.shader` draws lit rock only — its distance haze is the scene-wide **Aerial perspective** pass below (since 2026-11-08; before that the ring carried its own 35 km haze because the scene GradientFog ended at 12 km and would have fogged it out). Lit per frame from the cycle's sun / moon DirectionalLights (`LightColor`, the sun's `SkyColor` as ambient). Sorting: everything sky-side must clear the ring's back edge (~42.8 km) plus the camera's offset, so terrainTest's SkyDome **Radius (m)** is 80 000 and the cycle's **Disk orbit radius** 55 000 (the disks orbit the world origin) — a dome inside the ring logs a warning; `SkyDome` raises the camera Z Far to cover its radius (never lowers it). At dusk the sun sets behind the rim (the light keeps lighting the world until the sun is down — the ring casts no shadow).
- **Aerial perspective** (2026-11-08, Mark: "things that are far away seem like they're far away … terrain and object colors become more white instead of being totally saturated … shouldn't make stuff impossible to see, just hard to discern using colors"): `Code/World/Environment/AerialPerspective.cs` → `shaders/environment/aerial_perspective.shader`, ONE full-screen pass at `Stage.BeforePostProcess` 500 (after the FarTrees ring at −100, before the underwater view at 1000) on whichever camera is live, from the scene depth — so ground, grass, trees, far cards, water, entities and the caldera ring all sit in the same air. Per pixel: optical depth = distance × air density averaged between the camera's altitude and the point's (sea level 0, 1/e per **Haze Scale Height (m)** 1000, so valleys fill first and high ground stays crisper); (1) **Desaturate Distance (m)** 1500 / **Max Desaturation (0–1)** 0.85 slides the colour toward its own luminance (half the hue gone at 1 km, nearly all by 4 km — shapes stay); (2) **Haze Distance (m)** 20 000 / **Max Haze (0–1)** 0.9 then lerps toward the cycle's preset horizon (warmed by **Sun Warmth (0–1)** 0.6 × the preset sun glow on the sun's side), capped so the far world is pale, never gone — a third hazed at the 8 km far-tier edge, two thirds at the caldera foot, the crest crisper. **Strength (0–1)** 0 switches it off; **Haze Colour (no cycle)** serves scenes without a cycle. Pixels whose depth is past 0.95 × the SkyDome radius (or 0.9 × Z Far without a dome) are sky and untouched — the dome IS the far colour; the sun / moon disks at 55 km take only the thin high-altitude air. It REPLACED the scene GradientFog (0.72 / 0.76 / 0.84, start 1 km, end 12 km — it hid everything past 12 km and did nothing inside 1 km) in terrainTest and lightingTest and the caldera ring's private haze; the cycle's old **Fog** slot is now **Aerial perspective**. Lives on the DayNightCycle object; tune its properties in the inspector during play.

## Lighting look (asset-side, Valheim recipe)

- No screen-space pixelation. The look is asset-side (Valheim recipe, Mark 2026-10-02): low-res textures + point filtering + faceted normals baked in the mesh (create_elm_tree.py shade_flat; PixelFlatShading on pixel_lit.shader for meshes that are not), optional point-sampled TextureNormal / TextureRoughness + PixelTexCoordScale on pixel_lit.shader (elm bark v76: colour, normal and roughness all from one height field), then the engine's normal sun/shadows, SSAO, fog, bloom, tonemap. **Per-texel lighting** (pixel_lit `PixelTexelLighting`, default on, Valheim sconce reference 2026-10-05): direct light + shadows are evaluated at the texel centre so each texel is one lit block; `PixelLightSteps` (local lights, default 6 bands — Mark 2026-10-05: torch fall-off must be steppy, not a glow), `PixelLightCutoff` and `PixelSunSteps` (default 0, the sun stays smooth — banding is for fires, torches and lanterns only; a 5-step sun was tried and rejected 2026-10-13) posterise on top. Indirect stays the engine's. Firelight wanders through `Environment/FireLightFlicker` (authored on the campfire prefab's FireLight child, created on the held torch / lantern lamp; wind gusts widen it) — never on the sun. Playground: Assets/scenes/lightingTest.scene (100 m uniformly scaled dev box — non-uniform scale breaks vertex normals — clovertree/whole + fly cam + standard post stack on the camera)

## Terrain runtime: sea, load screen, fly camera, ground material (`Code/World/Terrain/`)

- Streaming, chunk mesh, biome population, world save IO. Sea = SeaWaves (CPU mirror) + SeaSwellTravelField (refraction march) + TerrainWorldManager.SeaWater / .SeaFoamMemory; shader code in Assets/shaders/sea_waves.hlsl (AGENTS.md "Water round 5"). The world-wide fields (lake shore distance, rivers, biome placement — `TerrainPreviewLandDiskFields.EnsureReady`, ~11 s on a fresh load) build on a worker behind "Preparing terrain…" and the chunks queue once they land (`TerrainWorldManager.WaitForWorldFields`; the water ticks wait too, they would block on the fields' lock) — on the main thread they froze the whole game at launch (Mark 2026-11-03). terrainTest's day / night cycle drives the scene's **Aerial perspective** haze colour (its **Aerial perspective** slot; the former GradientFog slot was empty until 2026-11-03): the haze follows the preset horizon, dark at night. A fog colour left at its daytime 0.72 / 0.76 / 0.84 lit far lakes and rivers pale grey all night — the water adds fog by its Fresnel weight, so the glow changed with view angle (Mark: "lighting artifacts from river water … at night … angle related"); the scene GradientFog is gone (2026-11-08), so the water shaders' `Fog::Apply` is now an identity and the pass hazes the finished frame by depth instead. The water's `SkyReflection` (water_common.hlsl) reads a reflected ray below the horizon AT the horizon, as the dome never shows the sky under it. The mountain ground tile is a light cool grey (create_ground_textures.py, 2026-11-03: "looks like piss, make it whiter"), and the splat's warm-dry macro hue skips the mountain (`SplatMacroHue` × (1 − mountain)). Water glints (riverwater / seawater.shader) are capped per light as a multiple of that light's colour (40× near → 1.5× at a 1.5 m pixel footprint) before the absolute 40 → 4 cap: the GGX 1 / (4 VdotH²) term runs to ~100× at a grazing far view, and with only the absolute cap a dim moon or torch made a 4.0 HDR blob that bloomed on a distant river (Mark 2026-11-03). The load screen stays up through "Generating map…" (the 512 px minimap raster runs behind it at 40 ms/frame) and then "Settling…" until 90 consecutive frames are under 16.7 ms or 30 s pass — never a lagging first look (Mark 2026-10-13). terrainTest: L toggles pawn ↔ fly camera; the fly camera carries TerrainFlyCameraAltimeter (top-left: elevation above sea level + height above ground, or water depth over a lake / the sea). Ground = materials/terrain/terrain_ground.vmat (+ _far) (pixel_lit F_TERRAIN_SPLAT, 2026-10-24: per-pixel biome blend — TerrainGroundSplat writes what each vertex IS (land shares + mountain in COLOR0, sand / wet / far canopy / tier in the UVs), the shader picks the biome per pixel like the resolver does with a noise-broken edge; five 512 px ground tiles (materials/terrain/ground_clover / redwood / amber / mountain / sand.png, all from Blender/scripts/create_ground_textures.py — grass blades + clover + bare soil, needle duff, wind ripples, worn scree, beach grain; 2026-11-03, Mark: "more realistic", Clover a bit darker, the other biomes darker too) tiled 4 m in world space = 128 texels / m, each tile with its coarse brightness divided out so the 4 m repeat never reads as a grid; two turned copies swapped in noise patches so no repeat shows; the large scale belongs to the shader: **Splat Macro Variation** (brightness at ~360 m and ~30 m) and **Splat Macro Hue** (a warm-dry / cool-lush drift, Mark 2026-11-03: "everything looks cartoony from afar"); **triplanar** since 2026-10-29 (Mark, voxel pit walls: "the vertical lines"): the tiles are projected top (xy) plus the x / y sides, weighted by the geometric normal^8, so level ground is still the one top projection and a dug wall gets the tile face-on — and the per-texel lighting shades a steep face at the texel of the projection that faces it, because walking the edge-on top texel flew the shadow lookup along the wall, one stripe per texel column with speckle)
- **Generated tilled soil** (2026-11-02, Mark: "can you make the wheat spawn on tilled soil?"): every wild-wheat cluster lies on a bed of dark tilled soil — a `TerrainGroundPatch` (cluster radius 1.5 m + `WildWheatTilledPadMeters` 1.2 = 2.7 m, ~6 beds / km² at chance 0.025, rim wobbled ±19 % by two hashed lobes, 0.75 m soft edge) planned by `TerrainVegetationScatter.PlanGroundPatches` on the chunk-sampling worker from the SAME cluster cell the wheat scatter uses (`TryPlanClusterCenter`, so bed and stalks share one centre), for the chunk's cells and its eight neighbours'. `TerrainGroundSplat.ApplyTilledPatches` writes it into the near chunk's splat with the hoe's contract — sand (TexCoord0.x) and the darkening channel (TexCoord1.x) both = coverage × 1.5, so pixel_lit's `step( 0.5, sand )` turns the darkening into **SplatTilledColor** earth brown (equal channels on purpose: sand running ahead of the darkening drew a pale sand ring). The chunk keeps the array (`LoadedChunk.GroundPatches`): the world grass plants no clump where coverage ≥ 0.5, `TerrainWorldManager.TilledAt` answers from it on undug ground (so `FarmingRules.IsTilledGroundAt` sows there — the bed is real tilled ground), and a voxel column dug there seeds its tilled paint from it (`VoxelField.SeedTilled`, before the strokes replay; the hoe's grass / bare paint can still paint over it). Near tier only (the far tier's darkening channel is the canopy). `world_find wheat` lists the nearest beds.
- **Clover stone** (2026-11-02, mineable 2026-11-03): `TerrainWorldManager.Stones.cs` — hand-harvest stones (pebble1–3 + rockpickup1) with the pickaxe-breakable rock_break1–4_v1 among them (**Vegetation - Clover — Rock Prefabs**), sectioned boulders rock_boulder1–3_v1 (~3 m) and sectioned stone spires rock_spire1–3_v1 (clearings only) as prop clusters; boulders and spires ride the tree pass. All but the pebbles are `MineableRock` (section by section with the pickaxe; unsupported sections burst into stone bits that rain down; models, LODs, prefabs and renders from Blender/scripts/create_mineable_rocks.py, on `rock_gunmetal.vmat` at 128 texels / m). Table + densities in the file and AGENTS.md *Forage, stone and generated tilled soil* / *Mineable rocks*.
